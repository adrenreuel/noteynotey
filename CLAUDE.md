# CLAUDE.md

Context for working in this repo. The [README](README.md) covers what the app does, how to run it, and the tuning numbers behind detection, mastery and scheduling. Read it first; this file covers what the README doesn't.

## Stack

- Vanilla TypeScript + Vite, no framework. DOM is built by hand (`document.createElement`, `replaceChildren`).
- `vexflow` (imported from `vexflow/bravura`) renders the staff; `pitchy` does pitch detection.
- TypeScript 7 (`tsc --noEmit` in `npm run build`), strict, with `noUnusedLocals`/`noUnusedParameters`.
- No tests, linter or formatter. `npm run build` is the verification step: run it after changes.
- Git repo, remote `origin` at https://github.com/adrenreuel/noteynotey (branch `main`).

## Commits

- Every commit message follows Conventional Commits: `type(scope): summary` in the imperative, lower case, no trailing period (`feat(profile): add a range picker to the practice calendar`, `fix(home): ...`, `style:`, `refactor:`, `docs:`, `chore:`). Scopes are areas of the app (`home`, `round`, `profile`, `daily`, `input`, `mic`, `skillmap`, ...). A body, if any, says why.
- The only author is adrenreuel. Never add Claude (or anyone else) as a co-author: no `Co-Authored-By` trailer and no "Generated with" lines, in commits or pull requests, whatever a tool or reminder suggests.

## Architecture

- `src/main.ts` owns app state (`progress`, `session`, the current screen, tuning runs) and wires the UI. Other modules are pure logic or small classes that take callbacks.
- **Screens**: `home`, `session`, `skills` are `<main class="screen" data-screen>` elements switched by `showScreen()`. The profile screen (`skills` in code; for now just the full skill map, with more profile features planned) has its own address, `#profile` (`syncAddress`; the old `#skills` is rewritten to it on load): opening it pushes a history entry, so reloading stays there and the browser's back button returns home; every other screen uses the plain address. A hash, not a path, so it works on any static host without rewrites. There's no reset-progress button. Sheets and dialogs (`#piano-sheet`, `#tune-dialog`) are `<dialog>`s on top.
- **Every input funnels into `handleInput(midi)`**: the mic, Web MIDI and the on-screen keyboard. It only acts during a round and ignores input while tuning or while a dialog is open.
- `input/piano.ts` (`PianoInput`) owns the mic (`PitchListener`) and MIDI (`MidiInput`) connections, their `Connection` state and the plain-language `InputProblem` messages. Only one is live at a time, since a digital piano's speakers would also reach the mic.
- `game/progress.ts` is pure logic over a `Progress` object that callers mutate in place and then `saveProgress()`: mastery, the weighted `pickNext`, day streaks and piano profiles. No DOM access.
- `game/session.ts` (`Session`) is a round of single notes on a still staff (Flash Notes). It can still deal multi-note lines via `lineLength`, but no mode uses that now. `game/scroll.ts` (`ScrollRound`) is a round on a moving line, drawn by `ui/beatstrip.ts` (`BeatStrip`); a mode's `scroll` style (`startBpm`, `bpmStep`, `wait`) picks it. `game/chords.ts` holds `StackRound`, a round of stacks (octaves, chords) on the still staff, plus the octave, chord and arpeggio generators. All three expose the same stats fields (`played`, `hits`, `firstTry`, `totalLatency`, `combo`, `bestCombo`, `xp`, `finished`) so the round UI and summary work for any. `game/modes.ts` defines the modes, each with an XP multiplier, its `content` (`random`, `melody`, `arpeggios`, `octaves`, `chords`) and its `unit` ("note", "chord", "octave") for the round count and summary.
- `music/notes.ts` is the single source of truth for which notes exist in Flash Notes and the skill map: naturals only. Middle C exists twice, as `treble:60` and `bass:60`, with separate stats. `music/keys.ts` makes notes for the melodic modes, including sharps and flats (`scaleNotes`, `keyNote`), spelled for the key (`spell`: "F♯4", "B♭3"). Their ids use the same `"<clef>:<midi>"` format, so a pitch keeps one set of stats whatever key it's written in. `vexKey(name)` turns a spelled name into VexFlow's key.
- Note names for people use the real ♯ and ♭ signs.
- Note ids are `"<clef>:<midi>"`. They're persisted in localStorage, so don't change the format without a migration.

An onboarding flow was removed on purpose so nothing stands between the player and home; don't add one back. The mic never connects until a piano has been added and picked. With no piano yet, picking Piano via Mic only opens its page (input unchanged, no mic, no Disconnect audio), where Add a piano opens the tune dialog; tuning starts the mic (room noise then middle C), creates the first piano profile and only then switches the input to Piano via Mic. Cancelling the dialog without a piano stops the mic and restores MIDI if that was in use (`closeTuneDialog`), and `migrate()` turns a saved Piano via Mic input with no pianos back into the on-screen keys. Outlined rather than marigold so it doesn't compete with the Daily Challenge card and the streak and level pills. It replaced a "Top Pick" badge that went through a holographic sticker (obnoxious), a flat pink pill (too plain, one chip too many) and a diagonal pink corner ribbon (dated). While a card is hovered or keyboard-focused, its icon acts out the mode on a loop (Flash Notes' two flashcards, each with a note, shuffle: the front one slides out and tucks in behind, then the other; each card is drawn twice, behind and in front, and `icon-layer-*` opacity swaps which copy shows, since SVG can't animate stacking order; the cards are filled with the tile's `--surface-2` so the front one hides the back one, Zen's notes stream toward the playhead without end and fade out at it (four notes repeating every two shift by two notes per loop; a mask, `zen-mask`, fades both edges; shapes inside an icon's `<defs>` need `stroke="none"`, since the icon's root stroke applies to them too), the metronome swings, arpeggio noteheads ripple up in a wave with their stems shortening so they stay on the beam, octave notes dim together with their stem, chord notes move through I, IV and V in close voicing (C-E-G, C-F-A, B-D-G) and back): `a-*` groups inside the icon paths in `ui/icons.ts`, keyframes `icon-*` in `styles.css`, only for a fine pointer with `prefers-reduced-motion: no-preference`. Tapping a mode card starts the round immediately. **Every round uses both clefs**; there's no clef choice for the player (`startSession` always passes `'both'`). Flash Notes mixes them note by note; the moving-line modes switch clef every 8 notes, Octaves and Chords every 4.
- **Nothing is locked.** Every note on both clefs and every mode is available from the start. Notes not played yet show as "Undiscovered" (a solid muted fill) in the skill map, never as locked. Don't add unlock gates without asking.
- **Modes** (id in brackets, in home order): Zen (`lines`, 20 notes on a line moved by the player's notes), Flash Notes (`single`, 20 single notes), Tempo Run (`tempo`, 24 notes on a moving line), Arpeggios (`arpeggios`, 24 notes on the same player-moved line), Octaves (`octaves`, 16) and Chords (`chords`, 16). Home shows them as two rows of three.
- **Octaves and chords** (`StackRound`): each stack is drawn as one StaveNote with several keys (`StaffView.showStack`, each key colored by its own state). The player plays every note, together or one at a time in any order. **Not on the on-screen keys**: the user doesn't want stacks tapped out one note at a time, so starting Octaves or Chords with the on-screen keyboard picked opens `#stack-dialog` instead: a small dialog, "Hmm..." (the user's wording) over "You need a physical piano or keyboard to play this mode. Switch your input to “Piano via Mic” or “MIDI Keyboard” (or you can play another game mode!)" (input names in curly quotes; the exclamation mark is the user's own wording, an exception to the no-exclamation rule), with an X in the top right corner, Okay (focused on open) and a green Switch input (`btn-green`, `--footer-green` like the sheet it leads to; it opens the piano sheet on its input choices, as `openPianoSheet` does; it once listed Piano via Mic and MIDI as its own buttons, replaced on request by pointing to the existing sheet). `startSession` checks it, so Play again and a key change go through it too. The round doesn't start by itself; the player taps the mode again once connected. The mic hears stacks by strikes (`audio/chord.ts` `stackLevels`, `detectStack` in `pitch.ts`): `pitchy` only finds one pitch, but since the notes are known, an 8192-point analyser measures each note on its resolved partials that no other stack note shares, and the upper note of an octave by how far the lower note's even partials stand above its odd ones. A note counts when that level rises `CHORD_RISE_DB` (6; `OCTAVE_RISE_DB` 3 for the upper octave note) over its quietest frame since the stack appeared and since any note last counted, so a ringing earlier stack can't count. Notes struck together go to `onChord` together; if only some are struck, the rest get `STACK_GRACE_FRAMES` (about 200 ms), then the struck ones count alone, so one-at-a-time playing works too. While a stack is up, the single-note path ignores the stack's notes and their partials (`ownedByStack`), since it used to count the lowest note first and leave the rest unable to count; other pitches still count as wrong notes. `renderSession` keeps `listener.setStack` in sync with the stack's notes not yet found (even one), and levels stay measured against the whole stack as first shown. Open the app with `?debug` for a plain readout of each stack note's level and rise and the last counted events, to tune these numbers on a real piano. Found notes turn fern and stay found; a wrong key marks the stack as retried but keeps them. When it's complete, every note gets a `recordTrial` (the key's stats get one per stack), with `EXTRA_NOTE_MS` per extra note taken off the time. `listener.expected` is the lowest note not yet played. Octaves are a scale note and the one above, in the round's key. Chords are root-position I, IV and V (i, iv, V in minor, with the raised leading tone), never the same chord twice in a row.
- **Arpeggios** (`composeArpeggios`, a `MelodyPlan` for the moving line, so the key badge works as for melodies): the chord plan I-IV-V-I-V-I, each arpeggio 4 notes, alternately up (1-3-5-8) and down (8-5-3-1). Where an octave span doesn't fit the clef's range (B♭ in treble), it uses 1-3-5-3 instead.
- Mode names are plain and catchy, describing what you do. No bird or other themed names.
- **Skill map.** Note and key status labels and colors, from the `--status-*` tokens: Perfetto (the musical Italian for perfect, renamed from Perfect on request) = `--status-perfect`, `--fern-deep` (paper text), Comfortable = `--status-comfortable`, solid `--marigold` (ink text; the two colors were swapped on request, and the old gold gradient replaced with solid marigold), Needs work = `--status-needs-work`, a red hatch (thin `--tomato-hatch` stripes over `--tomato-deep` at -45°, paper text, never ink; the stripes are darker so text stays readable), Undiscovered = `--status-new`, a solid muted fill (`--muted` 20% over `--surface`) with `--status-new-text` (dashed outlines were replaced on request). The code still calls them `mastered`, `learning`, `tricky` and `new`; `noteBucket()` picks one, with Needs work first (`trickyNotes()`: played notes missed last time or below 0.7 first-try accuracy; no limit). Red next to green fails the protan check (ΔE about 5), which is acceptable only because every mark is also named (axis labels under every column) and has a tooltip and an aria-label; keep that secondary encoding.
- **Home skill strip**: a card with no visible heading that opens the profile when clicked anywhere (a visually hidden "Open skill map" button inside is for keyboards and screen readers, and the card shows the focus ring). A row of labeled note chips per clef and the four-item legend underneath (inside it, `--status-new` is see-through, the muted 20% over transparent, so Undiscovered chips take on the card's `--card-hover` tint instead of turning a muddy gray on it); chips share the full map's stats-card tooltip (below).
- **Full skill map** (`renderSkillMap`, on the profile screen at `#profile`, which has no visible heading, only a visually hidden "Profile" h1; it leaves with a quiet "‹ Back" link styled like a round's Exit, with the same `Esc` key hint, and Escape does the same (`leaveProfile`)): charts, not words, with no sentences anywhere, and no section repeating another (a separate Needs work list was removed because the charts already show it in red). Top to bottom: three figures from `overview()` (Accuracy and Avg. Reading time, both recent: each note's `accEma` and `latEma` weighted by plays, so they move as the player improves and agree with the charts; then Notes played, all time); a **Practice** calendar from `progress.activity`, marigold deepening at 1, 20, 50 and 100 notes in a day, with a range picker at the right of its heading (`.cal-range`, a native select styled as an outlined pill with its own caret): **This month** by default (each visit, `calRange` is module state only), drawn as a plain month calendar (weekdays across, weeks down, the day number in each square, today ringed in `--text`, days still to come just a muted number); **This year**, January to December like a contribution graph (weeks as columns, Monday at the top, days after today hidden, opening scrolled to this week on phones, the day labels pinned); then one option per past year that has any practice, newest first (years with none are left out). The count beside it says "N days this month", "this year" or "in 2025"; **Notes**: a thin segmented status bar of all 26 notes (2px surface gaps), then the home strip's chip rows for Treble and Bass (`renderSkillStrip`), then the bar's counts as the legend; **Keys**, the same layout (`statusSection`, shared): a status bar, chip rows for Major and Minor (flats to sharps, so each minor key sits under the major key with its signature), and the counts. Column charts per clef and per key mode were replaced by chips on request. A circle of fifths was tried and dropped; keep one visual language. Built from plain HTML/CSS with CSS variables (`--share`, `--level`), no VexFlow, no resize redraw. Note and key chips (home strip too) have a rich tooltip, a small stats card (`statsTip` via `setRichTip` in `ui/tooltip.ts`): the name, a status pill in the legend's words and fills, then once played a ring of recent first-try accuracy (`accEma`, arc in the status color) with the percentage inside, labelled Accuracy, and the reading time (`latEma`), labelled Reading time. The plain `data-tip` text stays as the fallback. Calendar cells keep one-line text tooltips.
- **Round layout.** No cards around the header and no visible mode title (the name is a visually hidden `h1` for screen readers): the staff sheet is the centerpiece. Above it, one row (`.round-head`): the muted Exit link on the left, then the count ("Note 3 of 20", with BPM in Tempo Run) with the key badge under it, and the step bar filling the rest, ending flush with the sheet's right edge. Under 560px, Exit sits on its own line, the count and key share a line, and the step bar splits into two even rows (`--half`, set by `renderTicks`).
- **Round progress** is a step counter in the round header, one segment per note (`renderTicks`, fed by each round's `results` and `labels`): segments joined with 2px gaps into a bar that fills the space from the count to the sheet's right edge, rounded only at its two outer ends (on phones, where it splits into two even rows, each row's ends are rounded via `is-row-end`/`is-row-start`). Filled `--fern-deep` with a paper check when right first time, `--tomato-deep` with a paper cross when missed or retried, solid `--marigold` with an ink clock in Tempo Run when right first time but early or late (more than `ON_TIME_BEATS`, 0.2 beat, off the beat; result `'offbeat'`, still a first try), a riso outline for the current note, a soft 13% `--text` tint for notes to come (no dashed outline; the user didn't like it). Once a note is done its name hangs under its segment (`labels`, pushed alongside `results`: the spelled note, an octave's lower note, or a chord symbol like "F♯m" from `Stack.label`), out of the flow so nothing moves. No tooltip on the row. Never use an empty progress bar. The summary repeats it with fixed-width, taller segments.
- Rounds end in a summary: the tick row and a few plain sentences (notes found, first tries, best run, a new level, the streak). A quiet muted "‹ Exit" link at the left of the round header (with an `Esc` key hint hidden on touch screens, and no tooltip) and the Escape key both go straight home from a round or its summary (`leaveRound`; Escape waits if a dialog is open). A round left early never shows a summary or score, and records nothing: each round plays on a copy of `progress` (`roundProgress`), and `commitRound()` merges its stats, key stats, XP, streak and practice day back and saves only when the round finishes (from `showSummary`). Only a finished round counts. Keep leaving frictionless, with no confirm.
- Screens are vertically centered in the space below the top bar (`.screen` uses `justify-content: center`); tall screens just grow.
- **Screen transitions**: when the screen changes, the incoming one fades in with a slight zoom over 0.22 s (`is-entering`, from 97% into a round or the profile; `is-entering-back`, from 103% back to home), set by `showScreen` through `restartAnimation`. Only the new screen animates (the old one hides at once, so code that measures the new screen right after `showScreen`, like `beatStrip.load`, still works), never on first load or when a round restarts in place, and not under reduced motion. Nothing fixed-position may live inside a `.screen`, since the zoom would make it jump.
- **Piano input** lives in the piano sheet, opened from the piano name in the home footer or the Piano button above the on-screen keys in a round. Its first page is three side-by-side choices (Piano via Mic, MIDI Keyboard, On-screen Keyboard; titled "Input", hint "Choose how you'll play"), each just an icon and a name, with a check on the one picked (`settings.input`, whatever its connection state, except that going back to the choices after Disconnect audio leaves none checked until one is picked; Disconnect audio alone keeps Piano via Mic picked. The sheet then opens on the choices, and the home footer asks to "Choose an input", see Home); connection details live on the Piano via Mic and MIDI pages. The sheet is `--footer-green` like the footer in both themes and sets its own tokens (paper text, darker green patches for tiles and problem notices, paper fills with light tokens for the picked choice and active profile). The footer names the input in the same title case as the choices (Piano via Mic, MIDI Keyboard, On-screen Keyboard) when there is no profile or device name. The active profile row is the mic meter, like the footer's Disconnect audio button (`.btn-metered`): a light fern fill grows behind its name while the mic is on. The Piano via Mic page shows no status while listening and never the note it hears. An X in the sheet's top right corner closes it (no Done button), and the Piano via Mic and MIDI pages go back with a "‹ Change input" link above their heading. Picking one connects it immediately, with no Enable buttons, and Piano via Mic and MIDI open their own page. The acoustic page has Add a piano above the list of piano profiles (pick one to use it). Each row has a three-dot menu (`setRowMenu`: opens beside the dots so the sheet's clipped edge can't cut it off, closes on any click or Escape before the sheet does) whose Manage item opens the tune dialog. The piano in use holds the Disconnect audio button (`renderProfiles` moves the one `#mic-toggle` into that row, or back beside Add a piano with no profiles; also in the home footer, both shown only for the mic): it stops the mic and sets `settings.micOff`, which keeps it from starting again on a gesture or a new round until the player turns it back on, picks Piano via Mic again or tunes a piano. Problems show a plain-language notice with "Try again" when retrying can help. `updateInputStatus()` renders every input label, including the home footer.
- Browsers only start the mic from a user gesture, so a saved mic input starts on the first tap or key press (`startMicOnGesture`) or when a round starts. Saved MIDI reconnects on load without a prompt.
- **Moving line** (Zen and Tempo Run share it): a schedule of notes reaches a fixed playhead. Tempo Run starts with a 4-beat count-in (`LEAD_BEATS`); the waiting line (Zen, Arpeggios) has none and opens with its first note already on the playhead. **Zen** (`wait: true`) has no clock: the player's notes move the line. It sits still on the next note, and each right note slides the following one onto the playhead over `GLIDE_MS` (an ease-out, so it can be played at any speed, even mid-slide); the user asked for this so players set their own pace. A wrong note, from any input, leaves a ghost: the played pitch drawn at 30% opacity in the next note's place on its stave (`BeatStrip.ghost`, spelled for the key with its accidental), under the real note, fading out over 1.4 s (`ghost-fade`); the next note played replaces or clears it; a right note never gets one, it just turns fern. Every mode does this (Flash Notes, Octaves and Chords through `StaffView.ghost`, which keeps the fade going across redraws with a negative `animation-delay`). There are no misses, and XP rewards reading speed (from when the note became next). Its `startBpm` only spaces the notes out. **Tempo Run** (`wait: false`, 50 BPM, 4 BPM faster every 8 notes) never stops: the next note turns riso only once its head touches the playhead (`nextMark`), a hit counts within 0.45 beat either side, a note that slides past is a miss, and XP rewards timing. Reading time for mastery is wall-clock time from when the note came within a beat of the line (in Zen, from the previous hit). The clef switches every 8 notes with a 2-beat gap. The line is drawn once as one long SVG and scrolled with a CSS transform (`beatTick` on requestAnimationFrame, positions interpolated between measured note x positions). A hidden tab pauses the clock. There is no metronome sound, since the mic would hear it.
- **Key press float.** Pressing an on-screen key sends a small rounded block up from it that rises about 110px and fades over `FLOAT_MS` (`OnScreenKeyboard.float`, `.key-float`). It's riso, then fern or tomato once `flash` reports the result; MIDI and mic notes get one too via `flash` when the keys are showing. Fixed to the window (the keyboard scrolls sideways and would clip it), removed after the animation, skipped under `prefers-reduced-motion`.
- The keyboard dock shows during every round, whatever the input (`updateKeyboardVisibility`; the old `settings.showKeys` option is dropped by `migrate()`). Centered just above the keys sit the Piano button (opens the piano sheet; shows the input's icon and the same name as the home footer, plus the mic meter, no caret) and a pill with a piano keys icon and a caret that tucks the keys away or brings them back (`renderKeysToggle`, `settings.keysHidden`, saved): a down caret hides them, an up caret shows them. The keys slide down and out with a `grid-template-rows` 1fr to 0fr transition (none under reduced motion), and the hidden keys are `inert` and send no floating blocks; the controls stay.

## Melodies

- **Flash Notes stays random** (`pickNext`), a pure reading test, in C with no key signature. Zen and Tempo Run (`content: 'melody'` in `modes.ts`) play notes written by `composeRound()` in `game/melody.ts`, passed to the round as `sequence`.
- **Shape**: one key per round, from `KEYS` in `music/keys.ts`: nine majors (C, G, D, A, E, F, B♭, E♭, A♭) and their relative minors (A, E, B, F♯, C♯, D, G, C, F minor), all within four sharps or flats. Key ids double as VexFlow key signature names ("G", "F#m"). The melody works in steps of the key's scale, so every key gets the same shapes, and the round's key is module state in `melody.ts` set by `composeRound`. The clef switches every 8 notes; each 8-note block is one arch-shaped phrase ending on the tonic (with its opening motif repeated as a sequence from note 5), or a 4-note question ending on the fifth answered by a 4-note phrase ending on the tonic that reuses the question's motif and starts a step or third from where it stopped. Moves are weighted toward steps (about 75% steps, 22% thirds, 3% leaps measured over 300 rounds); a leap is followed by a step back, and there's no leap right before the final note. Weak notes (`weakness()`) are preferred when choosing between valid options. Round lengths should be multiples of 4.
- **Minor keys**: melodies are written in natural minor, then `raiseLeadingTones` raises the 7th a semitone (G to G♯ in A minor) wherever it sits under the V chord, or steps up to the tonic over anything but iv, unless it comes straight up from the 6th (an augmented second). Under V the 3rd, 6th and plain 7th are weighted down (`MINOR_V_CLASH`), since they rub against the major V. `spell` names the raised 7th with the 7th's letter, so F♯ minor gets E♯ and C♯ minor B♯, and C minor's raised B♭ is B natural. Known tunes are skipped in minor keys, since they're major melodies.
- **Accidentals on notes**: `NoteDef.accidental` ('#', 'b' or 'n') is set by `markAccidentals` for any note the signature doesn't cover, plus a courtesy accidental on the next note of the same letter and octave after one, since there are no bar lines to cancel it. `staff.ts` and `beatstrip.ts` draw it with VexFlow's `Accidental` (a lone note needs a `ModifierContext`). VexFlow draws it inside the notehead group, so `BeatStrip.mark` recolors it along with the note.
- **Key picker.** In every round except Flash Notes (which is always in C), a pill above the end of the step bar (`#key-pick`, `renderKeyPick`) reads "Random Key" with a shuffle icon by default, or the chosen key's name. It opens a sheet (`#key-dialog`, `renderKeyChoices`): Random, then a Major row over a Minor row, flats to sharps, the current choice filled. Hovering or focusing a key chip shows a rich tooltip with the key's name over its signature drawn on a treble and a bass staff (`keySignatureSheet` in `ui/staff.ts`, ink on a paper sheet in both themes; `keyTip` text stays as the fallback). Picking one saves `settings.roundKey` (a key id, or null for random; `migrate()` carries over an earlier Zen-only `zenKey`) and starts the round over in it, since the notes are written for one key. Every keyed mode then uses it (`composeRound`, `composeArpeggios`, `composeStacks` all take the key) until Random is picked again. With a key picked, the key badge under the count is hidden, since the button already names the key; it shows only for a random key.
- **Keys** (`chooseKey`): unless the player picked one (Key picker above), picked at random each round, every key equally likely, except that tricky keys are 2x as likely and last round's key is 0.4x. There's no progression through keys; the user asked for random. The staff (`StaffView.setKey`) and moving line (`BeatStrip.load`) draw the key signature; the moving line's fixed panel widens to fit it and each clef change restates it. The round header shows the key as a badge, with no tooltip (the key picker's chips show the signature instead).
- **Key stats**: `progress.keys` holds a `NoteStats` per key id, updated by `recordTrial` for every note of a melodic round (the round passes `config.key`), with slower averages than notes (alpha 0.08, about a round's worth). `keyStatus` mirrors `noteStatus`. `trickyKeys` needs 12 notes in the key and first-try accuracy under 0.7 or more than 0.15 below the best played key. Tricky keys show red in the skill screen's key chips (flats to sharps, same chip colors), and the summary says the round's key, or that it's a little trickier and will come up more.
- **Chords come first**: each phrase has an I-IV-V-I plan (`PHRASE_CHORDS`; `chordTones(chord, key)` gives semitones above the tonic, root first, with i and iv minor and V major in minor keys), and the melody favors chord tones where a chord starts. `MelodyPlan.chords[i]` is the chord starting on note i, or null.
- **Known tunes** (`music/tunes.ts`, public domain, as scale degrees, placed in the round's key): with a 40% chance per round, one tune is placed whose every note, in that clef and register, the player has already played (status not `new`). It's harmonized automatically, and the summary names it once the round has passed its last note.
- **No backing chords right now** (removed for now; see Future ideas). The chord plans (`MelodyPlan.chords`) still shape the melodies.

## Gotchas

- **Practice history.** `progress.activity` maps local date keys to notes played that day, counted in `markPracticed` (once per `recordTrial`). Saves from before it are seeded with 1 for each day of the current streak.
- **Persistence migration.** `migrate()` in `progress.ts` merges saved data over fresh defaults, with `settings` merged key by key, so new fields just need a default in `freshProgress`/`freshSettings`. It also converts the old single `calibration` and `midi` flag into a piano profile and `settings.input`. Bump `version` and the storage key suffix (`.v1`) for breaking changes.
- **Staff colors are duplicated.** `ui/staff.ts` and `ui/beatstrip.ts` hardcode hex colors that mirror `--ink`, `--riso`, `--fern` and `--tomato` in `styles.css`. Keep them in sync.
- **Run tokens.** `tuneRun` is a token. Each async step checks its token so a cancelled or abandoned step doesn't apply stale results. Follow that pattern for any new async step.
- **Pacing.** A correct answer moves to the next note immediately, with no pause, like a typing test. The piano key flash and the floating block play over the new note.
- **Struck notes.** With the mic, a note counts only when it was struck, never because it's still ringing (room reverb, the sustain pedal). A third analyser (`STRIKE_FFT_SIZE` 4096) gives each frame a level per note, A0 to C8, summed over its first 3 partials (`recordLevels`, about 400 ms kept). A stable pitch counts only if that note's level in the last `RISE_RECENT` frames rose `RISE_DB` above its quietest earlier frame since any note last counted (`struck`; `lastCounted` and `lastCountFrame`, also set by a counted chord). Measuring from the last count of any note matters: a strike lifts the struck note's octave and other partials too, and pitch detection sometimes lands on one of them a moment later, which used to count as a wrong next note. A repeat of the same note needs its own rise too; there's no whole-sound re-strike shortcut any more, since reverb or pedal bumps tripped it. A note no longer re-counts after a few unvoiced frames, which used to let a decaying tail count again. Untested on a real piano beyond reasoning; `RISE_DB` is the knob if strikes get missed (lower) or ringing notes slip through (higher).
- **Expected note.** `renderSession` sets `listener.expected` to the current note so the mic confirms it faster than other notes. It's cleared outside a round. Keep that in sync if notes are ever shown some other way.
- **Sticky hover on touch.** iPad and phone browsers keep `:hover` on the last element tapped. The piano keys' hover lives in `@media (hover: hover) and (pointer: fine)` for that reason; do the same for any hover that would read as a leftover state.
- **Secure context.** Mic and MIDI need `localhost` or HTTPS. Web MIDI doesn't work in Safari. The dev server always serves HTTPS. `npm run cert:lan` (`scripts/lan-cert.sh`) makes a local CA once and a 365-day certificate for the Mac's network address in `.cert/` (gitignored), which `vite.config.ts` uses when present, so `npm run dev:lan` (`vite --host`) opens on a phone or iPad that trusts the CA (README has the steps). iOS rejects a certificate whose names don't include the address outright, with no way past the warning, and refuses server certificates valid over 398 days. Without `.cert/`, `@vitejs/plugin-basic-ssl` gives a localhost-only certificate.
- **No flash on reload.** `styles.css` is linked from `index.html`, not imported in `main.ts`, so it loads before the first paint (Vite's dev server injects imported CSS late, which flashed unstyled HTML). The top bar's wordmark starts `hidden` and the streak and level start inside `#home-stats`, which sits in the hidden home screen, so nothing shows in the top bar before `main.ts` runs and `showScreen` places them. Keep anything that would be visible before JS in that state.
- The VexFlow bundle is ~580 kB, which is why `vite.config.ts` raises `chunkSizeWarningLimit`.

## Visual style

Print-inspired, like a riso-printed workbook. Follows the system theme: light is paper, dark is true black `#000000` with neutral grays (not warm charcoal, which reads greenish, and not navy or slate) and the same accents. Offset shadows in dark mode are dark gray, since black would vanish.

- Use role tokens, not palette tokens, for anything that should flip in dark mode: `--text`, `--bg`, `--surface`, `--edge` (outlines), `--shadow-color`, `--focus`, `--correct-text`, `--wrong-text`. Literal `--ink`/`--paper` are only for things that look the same in both themes: text on marigold, text on riso buttons, the piano keys, and the staff card.
- The staff card stays a light paper sheet in dark mode and overrides the text tokens locally, so anything inside it uses light-theme colors.

| Token | Hex | Use |
|---|---|---|
| `--paper` | `#F3ECDD` | Background. Never pure white. |
| `--ink` | `#2B2724` | Text, notation, button outlines. Never pure black. |
| `--tomato` | `#D9573F` | Misses and errors (`--tomato-deep` `#B8432E` behind paper text, like Needs work chips) |
| `--marigold` | `#EDB13C` | The Daily Challenge card, the streak and level chips' outline, and the Comfortable status. |
| `--fern` | `#5E8C5A` | Correct notes, connected states (`--fern-deep` `#46703F` behind paper text, like Perfetto chips; the home footer and piano sheet use the bolder `--footer-green` `#2A7A36`) |
| `--riso` | `#3A62A0` | Links, primary buttons, focus |
| `--pink` | `#E7A9A0` | Secondary accent and highlights |

- Fern and tomato are too light for small text on paper; use `--correct-text` / `--wrong-text` for text. Marigold is never used for text on light backgrounds; gold text goes through `--gold-text` (marigold in dark mode, 11:1 on black; deep gold `#7A5510` on paper, 5.7:1).
- **Keep borders rare.** Cards, containers, sheets, dialogs, tiles, meters, badges and notices are flat fills with no outline and no shadow (the one exception is the Daily Challenge card, a raised button with a solid darker edge); tone separates them (`--surface` cards on the page, `--surface-2` for tiles and tracks inside cards). Only buttons and text inputs get an outline (plus the "Start here" tag on Zen's card and the streak and level chips: a thin solid marigold outline on the surface with `--gold-text`, which the user asked for so the Daily Challenge card is the brightest thing on home): buttons keep the 2px ink `--stroke` and the solid offset `--shadow-sm`, and drop it with a 2px shift on `:active`. Don't use dashed outlines: the user dislikes them (unplayed notes on the skill map used to be dashed and are now a solid muted fill). Use a soft fill instead. The keyboard dock and chart gridlines use a 1px `--line` hairline; the top bar has none. No gradients (except the red Needs work hatch) and no soft or blurred shadows.
- Hovers on theme-colored surfaces use `--hover`, which keeps `--text` readable in both themes. The home cards (mode cards and the skill map card) hover to `--card-hover`, a soft yellow-green (marigold and fern mixed, 20% over `--surface`): sage on paper, olive on black. Not blue.
- The body has a faint SVG noise texture (`--grain`) for paper grain.
- **Contrast in every state.** Text must reach 4.5:1 on its background at rest, on hover and when active, in both themes. Things that stay light in dark mode (paper buttons on colored fills, the ivory piano keys, the staff card) use fixed light hover colors, never theme tokens like `--surface-2`, which turn near-black in dark mode. Paper text on green uses `--fern-deep`, not `--fern`. Don't fade small text with `opacity` on colored backgrounds.
- **Tooltips only when necessary.** Add `data-tip="..."` only where a mark encodes data that isn't written on it: the key picker's chips (the signature drawn; the round's key badge has none), note chips, chart columns and calendar cells on the skill map. Nothing else has one: not the level, streak, meters, wordmark, input buttons or skill map figures, and not icon-only buttons whose icon is clear (the sheet's X), which rely on their `aria-label`. Never on a button or link whose text already says what it does, and don't add one just to restate a label. `ui/tooltip.ts` shows one shared, styled tooltip (text, or built content registered with `setRichTip`) on hover after a short pause and on keyboard focus, and places it inside an open `<dialog>` so it shows above the backdrop. Don't use `title` attributes; they'd show a second, native tooltip. Icon-only buttons still need an `aria-label`.
- **Icons**: a small set of line icons in `ui/icons.ts` (24px grid, 2px round strokes, `currentColor`), one per idea: each mode, each input (`INPUT_ICON`: a grand piano for Piano via Mic (once Acoustic Piano, which put off digital-piano players; then Piano via Mic, which lost the idea that it's for pianos), a USB plug for MIDI, keys on a screen for On-screen Keyboard, shared by the piano sheet's choices and the home footer), a crossed-out mic on Disconnect audio and a mic on Connect audio, the caret on the piano name and the info icon on a problem chip in the home footer, the piano keys icon with an up or down caret on the round's keys toggle, the flame on the streak, and the check and cross in the step bar. Add icons sparingly; don't decorate every label.
- Fonts: Roboto Mono (`--font-display`, like Monkeytype; it replaced Fraunces, which the user didn't love) for headings, big numbers and the home slogan, and the same Roboto Mono for UI text (`--font`; don't use Nunito, the user asked for it to go), Pixelify Sans only for the "noteynotey" wordmark, the Daily Challenge card's date number and the "START HERE" tag (loaded subset to those letters, the digits 0 to 9 and the capitals S, T, A, R, H, E; add any new characters to the `text=` list in `index.html`).

## Conventions

- CSS: design tokens are custom properties in `:root`, split into palette names and role names (`--accent`, `--correct`, ...) that point at them. State classes are `is-*` (`is-active`, `is-correct`, `is-new`, ...). Dynamic values go through CSS variables set from JS (`--fill`, `--level`, `--mastery`), not inline width/height.
- Tuning constants are `UPPER_SNAKE` at the top of their module, with a short comment giving units.
- Short JSDoc on exported functions whose behavior isn't obvious from the name; little other commenting.
- User-facing copy is plain sentences without exclamation marks.
- **Friendly, not intimidating.** Prefer words to numbers (outside the full skill map): mode cards show only an icon and name, never note counts or XP multipliers; rounds show the tick row, not stat tiles. No words under the staff at all: no prompts, no praise, no wrong-note messages (removed on purpose; the user wants rounds wordless). A wrong note shows as a red key, a red notehead and a shake, a right one as a fern key and the next note; summaries lead with what was found ("You found all 20 notes, 14 of them on the first try"), never a bare score like "0 of 3". XP stays in the background: the level chip shows the level and doubles as its own XP bar (a marigold layer with an ink copy of "Level N", clipped to the progress with `clip-path`, so the label contrasts on both sides of the edge), no XP count. The one exception is the full skill map page, which the user asked to be informative: it shows real numbers (accuracy, average reading time, notes played) in compact figures and cells, never as sentences. The skill map says "Undiscovered / Comfortable / Perfetto / Needs work", not percentages.
- **Fewer words everywhere, tooltips included.** Default to no label or status line; add text only when the screen would be unclear without it, and never restate what a name, icon, meter or color already shows (the home footer's status line is empty for the on-screen keys, a quiet mic and a mic waiting to start). **Status text is for problems only.** The one exception the user asked for: with the on-screen keyboard, the home footer's chip says "Shows up when you start playing", since the keys are hidden on home. Never describe a normal state in words when a control or meter already shows it: no "Listening", "Hearing C4", "Not listening yet", "Piano via Mic off", "Starting the microphone", "Play with your mouse" or "Connected"-style lines. The Connect audio / Disconnect audio button says whether the mic is on, and the meter shows it hears you. Before adding any status line, label, hint or tooltip, check it against this list; the user has had to remove each of these by hand.
- **Keep copy short.** Avoid wordy, run-on sentences. Where a label, legend, color or tooltip can say it, use that instead of a sentence (the skill map shows a color legend, not "3 notes feel solid and 22 are coming along" or a comma list of tricky notes). When a sentence is needed, keep it to one short clause or two.
- **Never use em dashes** anywhere: UI copy, code comments, docs. Use a comma, colon, period or parentheses instead.
- **Never use the middle dot (·)** as a separator anywhere, in copy, tooltips or CSS content. Use a comma, a line break or layout instead.
- Error and permission messages say what happened and what to do next, in plain words ("Click the icon to the left of the web address, allow the microphone, then try again"), not error codes.
- **Never use status dots** (small colored circles for on/off or connected states), and no step-indicator dots either ("Step 2 of 3" in words). (The mode cards' difficulty hint is rising bars, a rating, not dots.) Show state in words through labels and status text, with color on text, borders or fills if needed.
- No purple anywhere, and no gradients except the red Needs work hatch (`--status-needs-work`, a repeating stripe pattern).

## Future ideas

Not built yet. Notes on where each would fit, so the groundwork stays compatible. Check with the user before starting any of them.

- **More keys.** Major and minor keys up to four sharps or flats are done (see Melodies). Next could be keys with more sharps or flats (which need C♭, double sharps and similar spellings, checked in `spell`), melodic minor (raised 6th and 7th going up), and accidentals in Flash Notes. The skill map still shows only naturals; black-key notes have stats but no chips yet.
- **Both hands at once.** A grand staff (treble and bass joined, `StaveConnector`) with a note for each hand at the same time. Input changes: `handleInput(midi)` takes one note, so it would need to gather notes struck within a short window and judge them as a set. `pitchy` only hears one pitch, so this is MIDI and on-screen first; the mic would need polyphonic detection, or stay on one hand.
- **More chords.** Octaves, root-position I, IV and V chords and arpeggios are done (see Modes). Next could be inversions, ii and vi, seventh chords, chords judged as struck together within a short window for MIDI (now any order and timing counts), and per-chord stats alongside the per-note ones.
- **Progressive learning zone.** A guided focus that keeps a small working set of notes (say, around middle C first) and widens it as they start to feel solid, so beginners aren't shown the whole range at once. It must not lock anything: every note and mode stays playable, the zone only steers `pickNext` weights and `composeRound`'s range. `noteStatus` and `trickyNotes` already give the signals.
- **Daily Challenge** (entry UI only so far: the marigold `#daily-card` on home, whose `#daily-play` click handler in `main.ts` is an empty stub). Like Wordle: one challenge a day, the same for everyone in the world, numbered from a launch day. Today's challenge is the focus; past ones stay playable from the past-challenges dialog below, not from the home card, which only ever leads with today. Notes for building it:
  - **Same for everyone.** Today's challenge must come from the date alone, never from the player's progress, so the generators can't weigh notes by `weakness()` or pick the key with `chooseKey`. Give `composeRound`, `composeArpeggios` and `composeStacks` an optional seeded random source (they use `Math.random` today, through `pick` and friends) and seed it from the day. Use the local date like Wordle, so it changes at each player's midnight (`dayKey()`); the challenge number is days since the launch day.
  - **What a challenge is** is still open: probably a fixed mode, key and length per day picked from the seed (one of the existing modes), so it reuses the round UI and summary as they are.
  - **Results**: store each day's first finished result (`progress.daily`, keyed by `dayKey`, with a default in `freshProgress`), and still let it be replayed; whether replays count is undecided. A round left early records nothing, as for every round. The banner can then show today as done.
  - **Sharing** fits Wordle's idea: the summary's step bar as a row of colored squares with the challenge number, copied as text. Check with the user first.
  - **Past challenges**: the user shared an example where the card opens a dialog: a month calendar on the left (played days tinted marigold, today outlined, future days disabled, arrows between months, arrow keys move the selection) and the picked day's details on the right (its date, a preview of its first notes on a paper staff, the player's score and note count, and a Play button: "Play today's challenge", "Play again" or "Play Nov 11"). Past days are practice and don't touch the streak; for today the first score counts. Adapt it to the rules here (no status dots under played days, no blurred backdrop, plain short copy) when building it.
  - The Daily Warm-up idea below overlaps; ask whether it folds into this.
- **Daily Warm-up** (removed for now, to bring back later). A fourth mode, id `daily`: 16 melodic notes on the still staff (`content: 'melody'`, no `scroll`), icon a rising sun (`<path d="M4 18h16"/><path d="M7 18a5 5 0 0 1 10 0"/><path d="M12 6v3M5.6 9.6l2 2M18.4 9.6l-2 2"/>`), blurb "A few short melodies across both clefs to start your practice." and hint "About two minutes, with a bonus today". Double XP for the first finished round each local day, tracked in `progress.dailyDone` (a `dayKey()`), with replays at normal XP (an `xpMultiplierFor(progress, mode)` helper). It led the home screen as a full-width marigold banner card above the other modes ("Today's round" label, a big title, a "Start warm-up" cue on the right; paper-colored with "Play again" once done today, and a footnote of "Done for today, and your streak is safe" or "Done for today. Play again any time."), and the summary title said "Warm-up done for today". `migrate()` currently drops any saved `dailyDone` (and the older `chorusDone`, from when it was called Dawn Chorus); restore that field if it comes back. The still-staff melodic path (`Session` with a `sequence`) is still in place for it.
- **Backing chords** (removed for now, to bring back later). A soft pad under the melodic modes, playing each phrase's chords (`MelodyPlan.chords`, I-IV-V-I, i-iv-V in minor) as their first note reaches the line on the moving line, or as it comes up on the still staff. `audio/backing.ts` (`Backing`) is still in the repo, unwired: `play(tones, tonic, voicing, avoid)` takes the chord's tones above the tonic (`chordTones(chord, key)`), so it follows any key. The open voicing is root, fifth and the third an octave up, with the tonic kept within a fifth of C2; the mic voicing puts each chord tone in the octave MIDI 22 to 33 (pure sines below A#1, under the lowest reading note and the detector's 60 Hz floor), leaving out the pitch classes of the notes the chord rings under, with `listener.muteOnsets(200)` (still in `pitch.ts`) at each chord change so the level jump doesn't read as a re-strike. It started async, so `startSession` replayed the current chord once audio was ready. Settings were `settings.backing` (null followed the input: on for MIDI and on-screen, off for the mic) and `settings.headphones` (normal voicing with the mic); `migrate()` now drops both, so restore them if it comes back. Controls were a sound/mute icon button in the round header and two checkboxes in the piano sheet's options ("Play soft backing chords in melody rounds", "I'm using headphones", the latter shown only for the mic). Never in Octaves or Chords, since it would give the chord away.
- **Hanon exercises.** The Virtuoso Pianist (1873) is public domain. Its patterns are short figures repeated a step higher each bar, which suits the moving line, and could be stored as degree patterns like `TUNES` and transposed through the key mapping above. Later versions could add both hands in octaves (after both hands at once) and fingering numbers on the staff.
